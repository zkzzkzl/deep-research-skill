# 证据与核验规则

本文件定义事实、来源、独立性和可信度。它保证检索过程可审计，但不承诺结论绝对正确。

## 一、证据类型

- `fact`：来源直接支持的事实。
- `source_view`：来源明确表达的观点、判断或预测。
- `inference`：基于已记录事实做出的简短推断。
- `recommendation`：建议，不属于本 skill 默认输出。

事实、来源观点和推断必须分开呈现。没有来源支撑的解释不得写成事实。

### 前瞻性内容（预测）的处理

- 官方机构、研究机构或公司自身发布的预测值与展望，按「机构预测 X」的形式记入事实卡：事实是「该机构作出了此预测」，预测用语（「或将」「有望」「预计」）不作为降低来源等级或可信度的依据。
- 涉及未来的结论不得写成事实，按 `source_view` 呈现，标注「（预测）」并注明预测机构与发布日期。
- 禁止把「机构预测 X」写成「X 将达到 / 已经达到」的断言式事实。

## 二、事实卡

关键数字、日期、人名、版本号和机构名称在引用前记录：

| 字段 | 含义 |
|---|---|
| `claim` | 待核实事实 |
| `value` | 数值或结论 |
| `unit` | 单位、货币和量纲 |
| `period` | 数据统计期间 |
| `as_of` | 结论或数据截止时间 |
| `source_id` | 来源编号 |
| `quote` | 原文短引用 |
| `published_at` | 来源发布日期 |
| `retrieved_at` | 实际获取时间 |
| `support` | 直接支持、部分支持或间接支持 |

输出只从事实卡组装。

## 三、来源等级

来源等级不等于内容必然正确，主要参考：

1. 是否是问题辖区、机构、数据或事件的一手发布者。
2. 是否提供原始数据、方法、样本、定义或合同。
3. 是否有编辑责任和可追溯作者。
4. 是否只是转载、聚合或评论区内容。

来源是否权威、内容是否真实支持结论，应分别判断。

### 可疑来源信号（降级为线索）

以下特征表示来源可信度存疑，命中内容不直接采信为事实，改道回一手来源或补独立印证后再入库：

- 转载聚合：聚合站、热门转载、自媒体洗稿，无法识别原始出处。
- 匿名信源与伪权威：「有专家表示」「据悉」「相关人士」，或以被动语态掩盖责任主体（「被认为」「普遍认为」）。
- 挑选性数据：只呈现有利区间、基期刻意选择、样本范围与结论范围不一致。
- 营销与推广语言：含产品推销、夸大承诺或引导性结论的内容。

信号只触发改道与补证，不单独否决来源：权威来源同样可能使用上述措辞，最终以来源等级和交叉印证为准。

## 四、独立性

独立来源组不能只是转述同一份通稿、论文、公告、数据集或采访。满足以下条件时视为同一上游：

- 引用同一发布机构。
- 复制同一份原始数据。
- 使用同一份采访或匿名信源。
- 没有新增方法、数据或独立核验。

来源谱系至少记录 `source_id`、发布机构和可识别的原始出处。能追溯共同上游时只计一个来源组。

## 五、可信度

- `已核实`：存在一个直接的一手来源，或至少两个相互独立的来源组结论一致。
- `推断`：由已记录事实推演得出，输出时说明依据。
- `未验证`：仅凭模型记忆、无法溯源，或只有单一二手来源且未获印证。
- `存在分歧`：可靠来源之间仍有实质冲突，不能强行合并。

整体报告不统一给一个可信度；应按关键结论分别标注。

## 六、时间和口径

每个关键数字记录：

- `published_at`：来源发布日期。
- `retrieved_at`：实际获取日期。
- `period`：数据统计期。
- `as_of`：结论适用的截止时间。

检查货币、单位、地区、自然年/财年、同比/环比、总量/均值以及季调口径。口径不同但数值接近时不得直接比较。

## 七、计算

对结论有实质影响的比率、增速、差值和量纲换算必须由计算能力完成。

没有计算工具时：

- 不自行生成关键计算值。
- 引用来源中已经计算好的结果。
- 标注「引用原文计算结果，未经验算」。

不改变结论的简单算术可以直接完成，但不得伪装成来源数据。

## 八、冲突处理

来源冲突时依次检查：

1. 是否使用不同统计口径或时间范围。
2. 是否存在数据修订或版本差异。
3. 哪一方更接近原始数据或事件。
4. 是否只是转载了同一错误上游。
5. 新来源是否真正增加了独立证据。

仍无法解决时呈现分歧，不挑选更符合预期的一方。

## 九、分析边界

- 可以整理来源中已有的解释、判断和预测，并标注为来源观点。
- 可以基于已记录事实给出简短推断，并说明依据。
- 不进行原创研究设计、长篇战略分析、投资建议、医疗建议或法律建议。
- 用户明确要求分析时，可以另建分析流程，但不改变本 skill 的检索定位。
